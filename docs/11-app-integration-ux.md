# 11 — 앱 통합과 신뢰 UX

[← 목차로](../README.md)

모델과 지식베이스와 도구가 준비돼도 사용자가 만나는 것은 화면입니다. 이 문서는 서비스를 앱으로 감싸는 골격(4-Tier, BFF, 세션)과, 사용자가 답을 믿고 쓰게 만드는 화면의 명세(출처 카드, 폴백 문구, 신뢰도 표현, 진행 표시, 사람 이관, 피드백), 그리고 AI 생성 고지와 대화 데이터의 거버넌스를 다룹니다. 플랫폼 편의 [④ 05 앱 통합 패턴](https://github.com/JaeHoYun/vcf-private-ai/blob/main/04-rag/docs/05-app-integration.md)이 RAG 조립 관점의 골격이라면, 이 문서는 서비스를 출시하는 앱 팀이 실제로 정해야 하는 것들의 정본입니다.

> 본 문서의 수치와 동작은 VCF 9.1.1 / PAIF 9.1.1 / PAIS 3.0 기준입니다(작성 2026-09). 규제 의무의 적용 범위와 시효는 [AX 방법론 부록 A2](https://github.com/JaeHoYun/enterprise-ax-methodology/blob/main/appendix/A2-kr-regulatory-timeline.md)가 단일 출처이며, 해당 여부는 법무 검토로 확정합니다.

---

## 11.1 골격 — 4-Tier와 BFF

어떤 서비스 유형이든 골격은 같습니다.

```
[클라이언트]  웹, 모바일, 사내 메신저 봇, 기존 업무 화면(임베드 코파일럿)
     │
[BFF]  사용자 인증, 세션, 요청 정형, 요청 속도 제한, 요청 ID 발급, 고지와 동의 상태
     │
[오케스트레이션]  검색과 조립, 또는 Agent Builder 엔드포인트 호출, 가드레일 훅, 승인 게이트
     │
[PAIS]  모델 엔드포인트, 에이전트 엔드포인트, 지식베이스
```

규칙은 두 가지입니다. **클라이언트는 PAIS를 직접 호출하지 않습니다.** 토큰이 클라이언트에 노출되고 사용자 신원이 끊기기 때문입니다([04 4.2절](04-identity-propagation.md)). **오케스트레이션 계층을 독립시킵니다.** 검색 전략, 프롬프트, 리랭킹, 가드레일을 이 계층에 모으면 모델과 인덱스를 바꿔도 클라이언트는 그대로입니다. 엔드포인트 호출의 인증, 스트리밍, 타임아웃과 재시도, 멱등은 [08 8.10절](08-agent-builder.md)에 코드와 함께 있습니다. 이미 외부 LLM을 쓰던 앱은 base URL과 키를 PAIS로 바꾸는 것으로 데이터 사내화를 먼저 확보하고, 그 뒤 인덱싱과 검색 삽입을 더하는 순서가 안전합니다([④ 05 5.2절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/04-rag/docs/05-app-integration.md)).

## 11.2 세션과 멀티턴

문서 Q&A는 후속 질문이 흔합니다. "그럼 그건?" 같은 질문을 그대로 임베딩하면 검색이 빗나갑니다.

- **세션 상태의 위치** — 대화 이력은 BFF나 오케스트레이션 계층에 보관합니다. Agent Builder 경로는 세션을 캡슐화하지만, 감사와 재현용 영구 이력은 앱 DB의 책임입니다([③ 04 4.4절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/03-serving-api/docs/04-agent-rag-api.md)).
- **후속 질문 재작성** — 직전 맥락을 합쳐 독립형 질문으로 다시 쓴 뒤 검색합니다.
- **컨텍스트 예산** — 이력, 근거, 질문, 출력 여유의 합이 창 안에 들어야 하며 이력은 요약이나 절단으로 줄입니다([03 3.4절](03-design-patterns.md), [05 5.5절](05-platform-consumption.md)).
- **세션 만료(TTL)** — 품질 파라미터이면서 동시에 보존 통제입니다(11.7절). 세션에 사용자 토큰 원문을 저장하지 않습니다([04 4.6절](04-identity-propagation.md)).

## 11.3 신뢰 UX 명세

사용자가 답을 믿는 근거는 백엔드 규칙이 아니라 화면에 보이는 것입니다. 다음 다섯 요소를 명세로 고정합니다.

**출처 카드** — 1차 진실은 실제로 검색된 청크의 메타데이터이고 모델이 본문에 쓴 인용은 보조입니다([④ 04 4.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/04-rag/docs/04-inference-integration.md)). 카드의 데이터 모델은 문서 제목, 원본 링크(사용자 권한으로 열리는 뷰어 링크), 등급 표시, 청크 위치(페이지나 절), 검색 점수(내부용, 노출은 선택), 인용 노드 ID(PAIS 3.0)입니다. 등급이 기밀인 근거는 카드에 등급을 표시하고 복사와 공유를 막습니다([06 6.4절](06-data-onboarding.md) 존 5).

**폴백 문구 세트** — 검색 점수가 임계 이하면 억지로 답하지 않고 "관련 문서를 찾지 못했습니다"로 폴백합니다([④ 03](https://github.com/JaeHoYun/vcf-private-ai/blob/main/04-rag/docs/03-retrieval-context.md)). 문구는 상황별로 미리 정합니다. 근거 없음, 권한 밖 문서만 검색됨(내용을 암시하지 않는 문구), 도구 실패, 승인 대기 중, 시간 초과, 서비스 점검 중. 각 문구에 사용자가 다음에 할 수 있는 행동(질문 바꾸기, 담당자에게 넘기기)을 붙입니다.

**신뢰도 표현** — 검색 점수나 모델 확률을 숫자로 노출하면 사용자가 과신하거나 무시합니다. 대신 세 단계(근거 있음, 근거 약함, 근거 없음)로 표현하고, 근거 약함이면 "확인이 필요합니다"류의 문구와 출처 확인을 유도합니다. 임계값은 개발자 파라미터로 두고 [13 13.7절](13-evaluation-guardrails.md)의 골든셋으로 조정합니다.

**진행 표시와 취소** — 다단계 에이전트는 응답이 수십 초에 이릅니다. 스트리밍으로 부분 응답을 보여 주고, 도구 호출 단계("문서 검색 중", "티켓 조회 중")를 진행 표시로 드러내며, 취소 버튼으로 연결을 끊어 생성을 멈춥니다. 타임아웃이 나면 "시간이 걸리고 있습니다"가 아니라 무엇을 다시 시도할 수 있는지를 알려 줍니다.

**AI 생성 표시** — 답변 영역에 AI가 생성했음을 상시 표시하고, 대외 채널이나 파일로 내보내는 산출물에는 11.6절의 표시 방식을 적용합니다.

## 11.4 사람 이관

에이전트가 정지 조건에 닿거나(문서로 풀리지 않음, 승인 필요, 신뢰도 낮음) 사용자가 요청하면 사람에게 넘깁니다([02 2.4절](02-use-cases.md)). 이관이 "티켓을 하나 만든다"에서 끝나면 담당자는 처음부터 다시 묻게 됩니다.

| 핸드오프 페이로드 | 내용 |
|-------------------|------|
| 대화 요약과 원문 이력 | 사용자 질문과 AI 답변, 요약은 AI가 만들되 원문을 함께 |
| 근거와 조회 결과 | 출처 카드 목록, 도구가 조회한 레코드 |
| 상태 | 무엇이 해결됐고 무엇이 남았는지, 승인 대기 중인 제안 |
| 신원과 권한 | 사용자 ID, 부서, 요청 ID([04 4.7절](04-identity-propagation.md)) |
| 서비스 수준 | 이관 후 첫 응답까지의 목표 시간과 담당 큐 |

담당자 화면에서 AI가 만든 초안을 그대로 쓸 수 있게 하되, 어느 부분이 AI 생성인지 구분해 보여 줍니다. 이관 건수와 이관 사유는 [02 2.6절](02-use-cases.md)의 자가 해결률 지표의 분모와 원인 분석에 쓰입니다.

## 11.5 피드백 루프

"좋아요와 싫어요 버튼을 단다"에서 멈추면 평가에 쓸 수 없습니다. 피드백은 이벤트로 남기고 평가셋으로 흘러야 합니다.

| 이벤트 필드 | 값 |
|-------------|----|
| 요청 ID, 세션 ID | BFF가 발급한 것과 동일 |
| 질의와 답변 | 원문(등급에 따라 마스킹, 11.7절) |
| 근거 | 검색된 청크 ID와 인용 노드 ID, 호출한 도구 |
| 구성 버전 | 모델 별칭과 실제 모델, 지시문 버전, 검색 파라미터 |
| 판정 | 좋음, 나쁨, 사유(부정확, 근거 없음, 권한 문제, 느림), 자유 텍스트 |
| 사용자 | 익명화된 사용자 ID와 부서 |

저장 위치는 앱 DB이며 개인정보가 들어 있으므로 11.7절의 보존 정책을 따릅니다. 나쁨 판정과 사유가 있는 항목은 주기적으로 골든셋 후보로 검토해 회귀 묶음에 넣습니다([13 13.7절](13-evaluation-guardrails.md)). 사용자에게는 피드백이 어디에 쓰이는지 한 줄로 알립니다.

## 11.6 AI 생성 고지와 표시 — 화면에 어떻게 적용하나

AI 기본법은 고영향 또는 생성형 AI 제품과 서비스에 AI 이용 사실의 사전 고지와 생성물 표시를 요구합니다. 하위 법령이 2026-07-21 시행되면서 표시 방식이 구체화됐고, 계도기간 동안에도 의무 자체는 발효 상태입니다[^ai-act]. 전사 방법론은 이 의무를 기존 통제에 연계하는 원칙을 다루고([AX 07 7.8절](https://github.com/JaeHoYun/enterprise-ax-methodology/blob/main/docs/07-organization-and-control.md)), 자산별 의무 점검표는 플랫폼 가이드에 있지만([⑤ 거버넌스와 데이터주권 갭 워크시트 B-0절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/worksheet/governance-sovereignty-gap.md)), 화면에 무엇을 어떻게 넣을지는 앱 팀의 몫입니다.

| 요구 | 화면과 산출물에서 | 결정할 것 |
|------|-------------------|-----------|
| 사전 고지 | 서비스 첫 진입과 도움말에 AI 이용 사실, 한계(부정확 가능성), 데이터 처리 범위를 고지 | 문안과 배치, 고지 확인 기록 여부 |
| 생성물 표시 | 답변 영역의 상시 표시. 파일로 내보내거나 대외 채널로 나가는 산출물에는 가시적 표시 또는 기계판독 방식(메타데이터, 워터마크) 중 정책이 허용하는 방식 | 산출물 유형별 표시 방식, 표시가 편집으로 지워지는지 |
| 내부 전용 서비스의 적용 범위 | 임직원만 쓰는 내부 서비스에 어디까지 적용되는지는 시행령과 고시의 해석에 따름 | 법무 확인 뒤 결정 기록에 남김. 확인 전에는 표시를 두는 쪽이 안전 |
| 고영향 AI 해당 시 | 설명 방안(결과와 주요 판단 기준)을 사용자에게 제공할 경로 | [02 2.9절](02-use-cases.md) 판정 결과에 따라 |

금융권은 감독 가이드라인의 보조수단성 원칙에 따라 최종 결정 책임이 사람에게 있음을 화면에서도 분명히 합니다(초안임을 표시하고 확정은 담당자가). 메신저 봇처럼 화면 공간이 좁은 채널은 첫 대화와 도움말 명령에 고지를 두고 각 답변에 짧은 표시를 붙입니다.

## 11.7 대화 데이터 거버넌스

질문과 답변과 추적 데이터는 개인정보와 기밀 발췌가 섞인 새로운 데이터 자산입니다. 플랫폼의 문서 수명주기 통제([⑤ 05 5.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/05-data-governance.md))가 문서 코퍼스를 다룬다면, 대화 데이터는 [⑤ 05 5.10절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/05-data-governance.md)이 정책을 정하고 이 절이 앱에서 무엇을 하는지를 정합니다.

| 항목 | 앱이 정할 것 |
|------|--------------|
| 대상 | 세션 히스토리, 프롬프트와 답변 로그, 피드백 이벤트, 추적 데이터(플랫폼과 공유). 각각의 저장 위치와 소유자 |
| 등급 | 근거로 쓰인 문서 중 가장 높은 등급을 상속하고 개인정보 플래그를 붙임 |
| 보존 | 운영 목적 이력(예: 세션은 만료 뒤 짧게, 로그는 조직 정책에 따른 기간), 감사와 규제 목적 기록(고영향 AI는 결정 근거 문서를 법이 정한 기간 보관), 프롬프트 본문은 등급별로 보존 허용과 마스킹 후 보존과 보존 금지를 구분 |
| 임직원 고지와 이용 정책 | 내부 서비스도 사용자의 질의가 기록되고 누가 볼 수 있는지 고지. 이용 정책(AUP)에 금지 입력(개인정보, 자격증명, 외부 기밀), 결과 검증 책임, 외부 반출 금지를 명시하고 처리방침에 반영 |
| 열람과 삭제 | 사용자가 자기 대화를 열람하고 삭제를 요청하는 경로. 삭제는 세션, 로그, 피드백, 추적 데이터, 캐시까지 전파 |
| 접근 | 로그와 추적 데이터를 볼 수 있는 역할을 최소로 두고 접근 자체를 기록 |

추적 데이터에 프롬프트 본문을 남기는 것은 디버깅과 평가에 유용하지만 그 저장소가 곧 발췌본 저장소가 됩니다. OpenTelemetry 수집기 단계에서 개인정보를 마스킹하거나, 본문 대신 해시와 길이만 남기는 옵션을 등급별로 정합니다([14 14.2절](14-operations.md)).

## 11.8 메신저 봇과 임베드 코파일럿

**메신저 봇** — 메신저 → BFF(웹훅) → 오케스트레이션 → PAIS. 응답은 스트리밍이나 분할 전송, 출처는 메시지 하단 링크 카드, 권한은 메신저 사용자 ID와 사내 디렉터리의 매핑으로 검색 필터에 연결합니다. 메신저의 메시지 보존 정책이 11.7절의 보존 정책과 다를 수 있으므로 어느 쪽을 따를지 정합니다.

**임베드 코파일럿** — 기존 업무 화면(ITSM, ERP, 문서 편집기) 안에 초안과 제안을 보여 주는 형태입니다. 사용자 신원은 그 업무 시스템의 세션에서 받아 BFF로 넘기고([04 4.3절](04-identity-propagation.md)), 제안을 적용하는 것은 사용자의 명시적 행동(버튼)이어야 합니다. 화면 안에서 AI 생성 부분과 사용자 작성 부분을 구분해 표시합니다.

## 11.9 결정 기록

1. 골격의 각 층을 어느 팀이 맡는가, 오케스트레이션 계층의 위치.
2. 세션 보관 위치와 만료.
3. 출처 카드 데이터 모델, 폴백 문구 세트, 신뢰도 세 단계의 임계값.
4. 핸드오프 페이로드와 이관 후 목표 시간.
5. 피드백 이벤트 스키마와 골든셋 편입 절차.
6. 고지 문안과 배치, 생성물 표시 방식, 내부 전용 서비스의 적용 범위에 대한 법무 확인 결과.
7. 대화 데이터의 등급, 보존, 고지와 이용 정책, 열람과 삭제 경로.
