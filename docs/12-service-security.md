# 12 — 서비스 보안 준비와 가드레일

[← 목차로](../README.md)

플랫폼 보안은 [⑤ 보안과 거버넌스](https://github.com/JaeHoYun/vcf-private-ai/tree/main/05-security)가 정본입니다. 이 문서는 그 통제 카탈로그를 서비스 하나에 적용하는 순서를 다룹니다. 앞 장에서 정한 위험 등급, 신원 전파, 데이터 소스 승인, 쓰기 작업 분류가 끝났는지 점검하고, 가드레일을 고르고 배치하며, 에이전트 위협 열 항목을 이 서비스에 대입하고, 자율성 상한을 적용하고, 레드팀을 실행해, PoC와 파일럿과 프로덕션 게이트를 통과하기까지 앱 팀이 준비하고 증명할 것을 정리합니다.

> 본 문서의 수치와 동작은 VCF 9.1.1 / PAIF 9.1.1 / PAIS 3.0 기준입니다(작성 2026-09). PAIS 3.0 릴리스 노트에 콘텐츠 가드레일(입출력 필터), 호출 단위 사람 승인, 최종 사용자 컨텍스트의 도구와 검색까지의 전파 기능은 없으므로, 이 문서의 통제는 모두 애플리케이션과 게이트웨이 계층의 설계입니다. 적용 전 최신 공식 문서로 재확인하시기 바랍니다.

---

## 12.1 이 문서의 범위 — 플랫폼 보안과 서비스 보안

같은 "보안"이라도 묻는 사람과 답이 다릅니다. 플랫폼 팀은 "전체를 어떻게 설계하고 어디서부터 시작하나"를 묻고, 앱 팀은 "이 서비스를 출시하려면 무엇을 갖추나"를 묻습니다. 앞의 질문은 [⑤ 00 어디서부터 시작하나](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/00-where-to-start.md)가, 뒤의 질문은 이 문서가 답합니다.

| 질문 | 플랫폼 보안(⑤) | 서비스 보안(이 문서) |
|------|-----------------|---------------------|
| 무엇을 통제하나 | 격리, 인증, 공급망, 데이터 거버넌스, 감사의 카탈로그와 검증 방법 | 그 카탈로그 중 이 서비스에 해당하는 항목과 앱이 직접 만드는 통제 |
| 누가 만드나 | 플랫폼, 인프라, 보안팀 | 앱 팀이 만들고 보안팀이 심사 |
| 무엇을 증명하나 | 통제가 존재하고 동작한다([⑤ 07 7.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/07-audit-compliance.md)의 C-01–C-18) | 이 서비스가 그 통제를 근거로 운영되고 서비스 고유 위험이 차단돼 있다(12.7절) |
| 에이전트 위협의 정본 | [⑤ 08 에이전트 보안 거버넌스](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md) | 그 위협을 이 서비스에 대입한 점검표(12.4절) |

이 문서를 읽는 시점은 구축(08–11)이 끝나고 출시 심사에 들어가기 전입니다. 다만 12.2절의 준비물은 설계 단계에서 이미 정해져 있어야 하며, 구축이 끝난 뒤에 처음 확인하면 다시 설계해야 하는 항목이 생깁니다.

이 문서의 통제는 앞 장의 결정을 입력으로 받습니다. 하나라도 비어 있으면 가드레일을 고를 기준이 없습니다.

| 준비물 | 정한 곳 | 이 문서에서 사용하는 곳 |
|--------|---------|---------------------|
| 위험 등급(낮음, 중간, 높음)과 자율성 상한 | [02 2.9절, 2.10절](02-use-cases.md) | 12.5절의 상한 적용, 12.7절 게이트의 무게 |
| 신원 전파 패턴(A, B, C)과 감사 로그 필드 | [04 4.3절, 4.7절](04-identity-propagation.md) | 12.4절 ASI03 점검, 로그 증적 |
| 데이터 소스 승인서와 소스별 등급, 보호 문서 인입 방식 | [06 6.6절, 6.9절](06-data-onboarding.md) | 12.7절 파일럿 게이트의 데이터 항목 |
| 작업 분류표와 승인 게이트 패턴, 킬스위치 위치 | [07 7.2절, 7.3절](07-integration-write-design.md) | 12.4절 ASI02, 12.5절 |
| 도구 목록과 MCP 서버별 등록 판정 결과 | [09 9.10절](09-mcp-tools.md) | 12.4절 ASI04 |
| 모델 엔드포인트(로컬, 공유, 원격)와 반출 정책 | [10 10.1절](10-models-serving.md) | 12.3절 원격 모델 추가 가드 |
| AI 생성 고지 문안과 대화 데이터 보존 정책 | [11 11.6절, 11.7절](11-app-integration-ux.md) | 12.7절 프로덕션 게이트 |

플랫폼 팀이 이 서비스에 배정한 것(네임스페이스, 토큰, 지식베이스, 쿼터)은 [05 5.1절](05-platform-consumption.md)의 온보딩 런북에 기록돼 있어야 합니다. 그 기록이 곧 이 서비스의 자산 목록이고, 플랫폼 팀의 인벤토리와 에이전트 레지스트리([⑤ 08 8.4절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md))에 같은 내용이 등록됩니다.

## 12.3 가드레일 선택과 배치

가드레일은 요청 흐름의 여러 지점에 적용하는 통제의 묶음이며, 지점마다 차단하는 대상과 맞는 도구가 다릅니다. 온프레미스에서 자체 호스팅할 수 있는 공개 후보를 지점별로 정리하면 다음과 같습니다. 릴리스, 라이선스, 한국어 성능은 도입 전 확인합니다.

| 가드 기능 | 무엇을 차단하나 | 후보 | 배치 위치의 기본값 |
|-----------|-------------|------|-------------------|
| 입력 인젝션과 탈옥 탐지 | 사용자 입력에 포함된 지시 변조(ASI01, LLM01) | Prompt Guard 2(소형 분류기), NemoGuard Jailbreak Detect NIM | BFF 또는 오케스트레이션의 입력 단 |
| 검색 청크와 도구 결과 살균 | 문서와 도구 응답에 숨긴 명령(간접 인젝션) | 규칙(숨김 텍스트, 제어문자, 지시형 문장 패턴)과 분류기의 병행 | 오케스트레이션 안, 컨텍스트 조립 직전. 게이트웨이는 이 컨텍스트에 접근하지 못하므로 앱이 맡는다 |
| 출력 콘텐츠 안전 | 유해, 정책 위반 출력 | Llama Guard 4, NemoGuard Content Safety NIM | 별도 가드 서비스 또는 1계층 게이트웨이의 응답 훅 |
| PII와 비밀 마스킹 | 개인정보, 인증정보, 내부 비밀의 노출(LLM02) | Presidio, LLM Guard 스캐너 | 출력 단과 로그 수집기 양쪽 |
| 주제 통제와 거절 | 범위 밖 요청, 역할 이탈 | NeMo Guardrails 대화 정책, 지시문의 거절 규칙 | 오케스트레이션 |
| 근거성 검사 | 검색 결과에 없는 단정(환각) | LLM 채점([13 13.7절](13-evaluation-guardrails.md)) | 출력 단, 지연 예산이 허용하면 |

**배치 결정** — 어디에 배치하느냐는 서비스마다 다시 고르지 않고 플랫폼 설계 결정 [⑦ D15](https://github.com/JaeHoYun/vcf-private-ai/blob/main/07-design/docs/06-decision-forks.md)를 따릅니다. 첫 서비스의 기본값은 앱 안 라이브러리(규칙과 소형 분류기)입니다. 조직에 1계층 AI 게이트웨이가 있으면([05 5.3절](05-platform-consumption.md)) 입력 탐지와 출력 안전을 게이트웨이 훅으로 이관할 수 있지만, 검색 청크와 도구 결과의 살균은 그 컨텍스트에 접근하는 앱 안에 유지합니다. 출력 가드는 어느 경우든 생성 모델과 분리된 계층에 배치합니다([⑤ 06 6.3절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/06-app-guardrails.md)).

**원격 모델을 사용하면 통제를 한 층 추가** — completion 엔드포인트가 원격 클라우드 모델이면 프롬프트에 포함되는 검색 청크와 도구 결과가 사외로 전송되므로, 인입 단 마스킹과 지식베이스와 도구의 반출 허용 목록이 추가됩니다([13 13.5절](13-evaluation-guardrails.md), [⑤ 05 5.6절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/05-data-governance.md)).

**지연과 한국어** — 가드 하나가 요청 경로에 수십에서 수백 밀리초를 더합니다. 어떤 가드를 동기로 적용하고 어떤 가드를 비동기(사후 탐지와 경보)로 운영할지 정하고, 종단 지연을 [14 14.2절](14-operations.md)의 관측으로 측정합니다. 공개 가드 모델은 영어 중심으로 학습된 것이 많으므로, 한국어 인젝션과 탈옥 문장을 골든셋에 넣어 탐지율을 직접 확인합니다([10](10-models-serving.md)의 한국어 선정 기준과 같은 절차).

## 12.4 에이전트 위협 점검표 — ASI01–10을 이 서비스에 대입

OWASP Top 10 for Agentic Applications 2026의 열 항목을 이 서비스에 대입합니다. 위협의 정의와 플랫폼 통제는 [⑤ 08 8.1절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md)이 정본이고, 여기서는 서비스 단위로 물을 것과 갖출 것만 적습니다. 단일 호출이나 RAG 서비스라면 도구가 없으므로 ASI01, ASI03, ASI06, ASI09만 해당합니다.

| 코드 | 이 서비스에서 물을 것 | 해당하면 갖출 것 |
|------|----------------------|-----------------|
| ASI01 목표 탈취 | 사용자 입력, 지식베이스 문서, 도구 응답 중 지시문을 덮어쓸 수 있는 경로가 있는가 | 12.3절의 입력 탐지와 살균, 출력 가드, 승인 게이트 |
| ASI02 도구 오남용 | 조회 도구로 범위 밖 레코드를 대량 수집하거나 쓰기 도구를 반복 호출할 수 있는가 | 작업 분류표([07 7.2절](07-integration-write-design.md)), 인자 검증과 레이트리밋, 다운스트림 쿼터([07 7.5절](07-integration-write-design.md)) |
| ASI03 신원과 권한 남용 | MCP 서버의 정적 토큰이 호출 사용자 권한을 초과하는가, 서비스 계정이 다른 서비스와 공유되는가 | 신원 전파 패턴 B 또는 C([04 4.3절](04-identity-propagation.md)), 서비스별 계정, 감사 필드 |
| ASI04 에이전트 공급망 | 도구, MCP 서버, 지시문 템플릿의 출처와 버전이 고정돼 있는가 | MCP 서버별 등록 판정 기준([09 9.10절](09-mcp-tools.md)) 통과, 도구 설명 해시 고정([09 9.7절](09-mcp-tools.md)), 지시문 형상관리([08 8.8절](08-agent-builder.md)) |
| ASI05 예기치 않은 코드 실행 | 코드 인터프리터, 셸, 스크립트 생성 도구가 있는가 | 샌드박스(커널 수준 격리, 네트워크 기본 거부, 자원 한도). 첫 서비스에는 넣지 않는 것이 기본 |
| ASI06 메모리와 컨텍스트 오염 | 세션 이력이나 장기 메모리에 사용자 입력과 도구 결과가 검증 없이 기록되는가 | 메모리 쓰기 권한 분리, 세션 이력의 살균, 인덱스 소스 승인([06 6.6절](06-data-onboarding.md)) |
| ASI07 안전하지 않은 에이전트 간 통신 | 에이전트가 여럿이고 서로 결과를 전달하는가 | 하위 에이전트 결과를 비신뢰 입력으로 처리, 상호 인증. 첫 서비스는 단일 에이전트([03](03-design-patterns.md)) |
| ASI08 연쇄 실패 | 한 단계의 오류가 다단계 쓰기로 확산될 수 있는가 | 단계와 시간 상한, 차단기, 보상 매트릭스([07 7.4절](07-integration-write-design.md)) |
| ASI09 사람과 에이전트 간 신뢰 악용 | 승인 화면에 근거 없이 요청만 전달되는가, 신뢰도 표시가 없는가 | 근거를 함께 표시하는 승인 화면([07 7.3절](07-integration-write-design.md)), 신뢰도 표현([11 11.3절](11-app-integration-ux.md)) |
| ASI10 이탈 에이전트 | 소유자, 만료, 퇴역 절차가 정해져 있는가 | 레지스트리 등록, 자격증명 만료, 퇴역 절차([14](14-operations.md)) |

이 표의 "갖출 것"이 이미 앞 장에서 만들어져 있으면 점검표는 확인만으로 끝납니다. 이 장에서 처음 만들어야 하는 항목이 많다면 설계 단계에서 놓친 것이며, 출시 일정을 조정하는 근거입니다.

## 12.5 자율성 상한 적용 — L1에서 시작하고 L2를 허용하는 조건

[02 2.10절](02-use-cases.md)에서 정한 자율성 상한을 실제 통제로 바꿉니다. 위험 등급과 자율성의 매트릭스는 [⑤ 08 8.3절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md)이 정본이고, 플랫폼 설계 결정으로는 [⑦ D16](https://github.com/JaeHoYun/vcf-private-ai/blob/main/07-design/docs/06-decision-forks.md)입니다.

**첫 배치 L1(행동마다 승인)에서 갖출 것**

- 승인 게이트가 에이전트가 우회할 수 없는 계층(도구 게이트웨이 또는 BFF)에 있고, 지시문의 "승인을 받아라"에 의존하지 않는다([07 7.3절](07-integration-write-design.md)).
- 킬스위치가 서비스 단위로 있고, 한 번의 조치로 에이전트 비활성화, 토큰 폐기, 도구 승인 해제가 일어난다. 작동 권한자와 위치가 레지스트리에 적혀 있다.
- 세션 단위 감사가 남는다. 요청 ID, 사용자, 에이전트 ID, 도구 호출과 인자(마스킹), 승인자, 결과([04 4.7절](04-identity-propagation.md)).

**L2(계획 단위 승인)를 허용하는 조건** — 다음이 전부 충족될 때 심사로 승격합니다.

1. 사람이 계획(행동 묶음)을 읽고 승인하는 화면과, 승인된 범위를 벗어난 행동을 거부하는 집행 지점이 있다.
2. 섀도 운영에서 채택률과 적중률이 [02](02-use-cases.md)에서 정한 임계선을 넘었다.
3. 12.6절의 레드팀 임계값을 통과했고, 승인 우회 시도가 0건이다.
4. 위험 등급이 낮음 또는 중간이다. 높음 등급은 L1을 유지한다.

**강등 트리거** — 승인 없는 실행 시도 1건, 도구 오남용 경보, 레드팀 재실행 미달, 소유자 부재 중 하나라도 생기면 자동으로 한 단계 강등하고 킬스위치를 검토합니다. 강등은 자동이고 승격은 심사입니다.

## 12.6 레드팀 게이트

레드팀은 출시 전 한 번이 아니라 게이트마다, 그리고 모델과 지시문과 도구가 바뀔 때마다 실행합니다. 도구체인은 용도별로 고르며, 상세는 [⑤ 08 8.9절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md)에 있습니다.

| 도구 | 이 서비스에서 언제 | 무엇을 확인하나 |
|------|-------------------|-------------|
| garak | PoC부터, 모델이나 지시문이 바뀔 때마다 | 알려진 취약 유형의 자동 프로브(인젝션, 누출, 유해 출력) |
| promptfoo | 파일럿 게이트의 CI 회귀 | YAML로 정의한 테스트 묶음과 OWASP 프리셋, 골든셋과 같은 파이프라인 |
| PyRIT | 프로덕션 게이트 전 수동 시나리오 | 다단계 유도와 탐색형 공격 |
| DeepTeam | 도구와 메모리가 있는 에이전트 | 에이전트 취약 유형 중심 시나리오 |

**임계값의 예** — 조직이 정하되 문서로 남깁니다. 인젝션 성공률의 상한, 승인 우회 0건, 출력의 PII 노출 0건, 시스템 프롬프트와 숨은 컨텍스트 누출 0건, 범위 밖 도구 호출 0건. 통과하지 못한 항목은 면제가 아니라 수정 대상입니다.

**회귀 편입** — 레드팀에서 발견한 우회 케이스는 [13 13.7절](13-evaluation-guardrails.md)의 골든셋에 영구 편입해, 다음 변경에서 같은 우회가 다시 통하지 않음을 CI가 확인합니다. 결과와 통과 여부는 레지스트리에 남깁니다.

## 12.7 PoC, 파일럿, 프로덕션 게이트의 서비스 보안 기준

세 게이트의 정의는 플랫폼 편과 같습니다. PoC는 합성 데이터나 공개 데이터로 사내 소수가 사용해 보는 단계, 파일럿은 실제 데이터를 한정된 사용자가 읽기 전용으로 사용하는 단계, 프로덕션은 그 제한을 해제하는 단계입니다. C-번호는 [⑤ 07 7.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/07-audit-compliance.md) 마스터 통제 체크리스트의 항목이고, 서비스가 그 통제를 근거로 운영됨을 증적으로 제시합니다. 앞 게이트의 항목은 다음 게이트에서도 유지돼야 합니다.

| 게이트 | 판정 항목 | C-번호 | 인정하는 증적 |
|--------|-----------|:---:|---------------|
| PoC | 서비스 인증이 SSO 또는 서비스 계정이고 공유 키가 없음 | C-02, C-03 | IdP 클라이언트 등록과 토큰 발급 설정 |
| PoC | 모델과 지식베이스가 승인된 출처에서만 반입됨 | C-06 | Model Gallery 반입 기록, 데이터 소스 승인 기록 |
| PoC | 요청 1건을 요청 ID로 앱, PAIS, 도구까지 재구성할 수 있음 | C-11 | 재구성 시험 결과([04 4.8절](04-identity-propagation.md)) |
| PoC | 실제 데이터와 개인정보가 포함돼 있지 않음 | 해당 없음 | 시험 데이터의 출처 기록 |
| PoC | garak 자동 프로브를 한 번 실행함 | 해당 없음 | 실행 결과 |
| 파일럿 | 위험 등급과 자율성 상한이 기록되고 AI 위험관리 책임자가 승인함 | C-17 | 레지스트리의 판정 기록([02 2.9절](02-use-cases.md)) |
| 파일럿 | 데이터 소스마다 승인서와 등급이 있고, 보호 문서를 인입했다면 복호화 승인과 로그가 있음 | C-16 | 소스별 승인 기록([06 6.9절](06-data-onboarding.md)) |
| 파일럿 | 검색단 권한 필터가 사용자 권한대로 동작함 | 해당 없음 | 권한 없는 시험 사용자의 질의 결과([04 4.5절](04-identity-propagation.md)) |
| 파일럿 | 입력 탐지, 살균, 출력 마스킹이 배치돼 있고 검증을 통과함 | C-07, C-09 | 가드 배치 구성과 검증 결과(12.3절) |
| 파일럿 | 도구가 있으면 작업 분류표와 승인 게이트가 있고 비인가 도구 호출이 거부됨 | C-08 | 작업 분류표([07 7.8절](07-integration-write-design.md))와 거부 시험 결과 |
| 파일럿 | 외부 MCP 서버마다 등록 판정 기준을 통과했고 도구 설명 해시가 고정됨 | C-18 | 등록 판정 기록([09 9.10절](09-mcp-tools.md)) |
| 파일럿 | 킬스위치가 작동하고 작동 권한자가 정해져 있음 | 해당 없음 | 작동 시험 일자와 결과 |
| 파일럿 | 세션 감사 로그가 변경 불가 저장소에 기록됨 | C-12 | 저장소 설정과 변경 시도 차단 결과 |
| 파일럿 | promptfoo 회귀가 CI에 포함돼 있고 임계값을 통과함 | 해당 없음 | CI 실행 결과(12.6절) |
| 파일럿 | 12.4절 점검표의 해당 항목을 모두 갖춤 | 해당 없음 | 12.4절 점검 결과 |
| 프로덕션 | 대외 노출이면 AI 생성 고지와 표시가 화면에 있음 | 해당 없음 | 화면과 산출물의 표시 결과([11 11.6절](11-app-integration-ux.md)) |
| 프로덕션 | 대화 데이터의 보존, 열람, 삭제 경로가 정책대로 동작함 | 해당 없음 | 경로별 시험 결과([11 11.7절](11-app-integration-ux.md)) |
| 프로덕션 | 품질, 드리프트, 오남용 경보가 운영 관측에 연결돼 있음 | C-13 | 경보 설정([14 14.2절](14-operations.md)) |
| 프로덕션 | 사고 대응 플레이북에 이 서비스의 킬스위치와 인덱스와 메모리 롤백 절차가 있음 | C-14 | 플레이북과 테이블탑 훈련 기록 |
| 프로덕션 | 수동 레드팀 시나리오를 실행했고 ASI 열 항목의 커버리지를 확인함 | 해당 없음 | 시나리오별 결과(12.6절) |
| 프로덕션 | 쓰기 도구가 있으면 멱등 키와 보상 매트릭스가 검증됨 | 해당 없음 | 중복 요청과 보상 시험 결과([07 7.4절](07-integration-write-design.md)) |
| 프로덕션 | 출시 심사 패키지가 제출됨 | 해당 없음 | 패키지([13 13.10절](13-evaluation-guardrails.md)) |
| 프로덕션 | 레지스트리의 상태가 프로덕션으로 바뀌고 소유자와 퇴역 절차가 적혀 있음 | 해당 없음 | 레지스트리 기록([14 14.12절](14-operations.md)) |

게이트 심사는 다음 기준으로 운영합니다.

- **판정 기준.** 게이트의 모든 항목이 증적으로 확인되거나 유효한 면제 상태여야 통과합니다. 면제는 사유, 만료일, 승인자가 모두 있어야 유효하고, 만료일이 지난 면제가 하나라도 있으면 통과하지 못합니다. 레드팀 임계값(12.6절)과 승인 게이트 관련 항목은 면제 대상이 아니라 수정 대상입니다.
- **무엇을 남기나.** 항목마다 판정 결과, 증적 링크, 면제한 경우의 사유와 만료일, 심사자와 심사일을 기록합니다. 이 기록은 출시 심사 패키지의 보안 준비 항목으로 제출되고, 레드팀 결과는 릴리스 매니페스트([13 13.9절](13-evaluation-guardrails.md))에도 남습니다.
- **누가 언제.** 앱 팀이 증적을 준비하고 보안팀이 심사합니다. 파일럿과 프로덕션 게이트는 AI 위험관리 책임자가 최종 승인합니다. 게이트에 진입할 때마다 심사하고, 모델, 지시문, 도구가 바뀌면 관련 항목을 다시 확인합니다.
- **어떻게 측정하나.** 게이트별 첫 심사 통과율, 면제 건수와 만료 임박 건수, 12.4절 항목 가운데 이 장에서 처음 만든 항목의 수를 측정합니다.
- **어떻게 개선하나.** 면제가 만료되면 재심사합니다. 처음 만든 항목이 많거나 같은 항목이 여러 서비스에서 반복해 미달하면 해당 설계 장(02, 04, 06, 07)의 기준에 그 항목을 추가합니다.

## 12.8 결정 기록

서비스를 심사에 제출할 때 다음을 확인하고 결정 기록에 남깁니다.

1. 가드레일 배치 지점과 후보(D15를 따랐는가, 서비스 고유로 바꾼 것이 있는가)와 동기 대 비동기 구분.
2. 자율성 상한(D16), L2 승격 조건의 충족 여부, 강등 트리거.
3. 레드팀 임계값과 최근 통과 결과, 회귀 편입한 우회 케이스 수.
4. 게이트에서 면제한 항목과 사유와 만료일.
5. 킬스위치의 위치, 작동 권한자, 마지막 작동 시험 일자.
6. 원격 모델을 사용한다면 반출 허용 목록과 인입 단 마스킹의 검증 결과.

다음 문서에서는 서비스의 품질을 **평가하고 출시 심사를 통과**하는 방법을 다룹니다. 측정 지표와 실패 유형, 골든셋과 채점, 프롬프트 수명주기, 릴리스 매니페스트와 A/B 트래픽 분할, 출시 심사 패키지가 주요 내용입니다.
