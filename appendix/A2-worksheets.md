# A2 — 워크시트

[← 목차로](../README.md)

본문에 흩어져 있는 판단 기준을 **채워 넣는 형태**로 모았습니다. 각 항목 끝의 링크는 판단 근거가 되는 본문으로 연결됩니다. 복사해 팀 문서로 사용하시기 바랍니다. 순서는 서비스 수명주기를 따릅니다. 유스케이스 선별과 위험 등급(A2.1, A2.4), 설계 계약(A2.5 신원, A2.6 쓰기, A2.7 보호 문서, A2.10 온보딩), 등록과 출시(A2.3 MCP, A2.8 보안 서명, A2.9 심사 패키지, A2.2 운영 투입 전 점검)입니다.

## A2.1 유스케이스 선별 워크시트

후보 업무 하나당 한 장을 작성합니다. 순서는 [02 2.8절](../docs/02-use-cases.md)과 같습니다 — 다섯 질문 → 실패 유형 점검 → 템플릿 기술.

| 후보 업무 | 작성자 | 날짜 |
|-----------|--------|------|
| | | |

**1) 다섯 질문** — 하나라도 '아니오'면 아직 사례가 아니라 리스크입니다([02 2.4절](../docs/02-use-cases.md)).

- [ ] 입력과 출력을 한 문장으로 적을 수 있다: ________
- [ ] 정지 조건(에이전트가 멈추고 사람에게 넘기는 시점)이 정의돼 있다: ________
- [ ] 틀려도 피해가 작다 — 초안, 분류, 검색처럼 사람이 중간에 넘겨받으면 되돌릴 수 있는 일이다
- [ ] 하나의 도구, 하나의 데이터원, 하나의 산출 형식으로 시작할 수 있다
- [ ] 도입 전후를 비교할 지표가 미리 있다: ________

**2) 실패 유형 노출 점검** — 각 유형에 대해 '어디서 방지하는가'를 적을 수 있어야 합니다([02 2.3절](../docs/02-use-cases.md)).

- [ ] **파일럿 정체** — 깨끗한 샘플이 아니라 실제 데이터, 예외, 감사 요건으로 검증할 계획이 있다
- [ ] **단일 진실원** — 검색 대상 데이터의 출처, 권한, 신선도가 정리돼 있다
- [ ] **에이전트일 필요** — RAG, 고정 워크플로로 충분하지 않은 이유를 적었다([01 1.1절](../docs/01-foundations.md), [03 3.1절](../docs/03-design-patterns.md))
- [ ] **거버넌스와 권한** — 도구 승인, 접근통제, 감사 로그 계획이 있다([09](../docs/09-mcp-tools.md))
- [ ] **평가 장치** — 골든셋과 섀도 운영 계획이 있다([13](../docs/13-evaluation-guardrails.md))

**3) 기술** — 위를 통과한 업무만 [02 2.5절](../docs/02-use-cases.md)의 여섯 항목 템플릿(상황, 하는 일, 왜 이 방식, 실패할 수 있는 곳, KPI, 구성 매핑)으로 기술합니다.

## A2.2 운영 투입 전 점검표

에이전트를 운영에 투입하기 직전 확인합니다([13](../docs/13-evaluation-guardrails.md), [14](../docs/14-operations.md) 기반).

**평가와 가드레일**

- [ ] 골든셋이 있고, 합격선을 정해 CI 게이트로 적용했다([13 13.7절](../docs/13-evaluation-guardrails.md))
- [ ] 되돌리기 어려운 도구 호출(쓰기, 전송, 결제)는 실행 전에 앱 계층 승인 게이트를 거친다([13 13.6절](../docs/13-evaluation-guardrails.md))
- [ ] 입력과 출력 필터 등 콘텐츠 가드레일을 앱 계층에서 설계했다([13 13.5절](../docs/13-evaluation-guardrails.md))
- [ ] 종료 조건(최대 단계와 시간 한계)이 설정돼 있다([03 3.5절](../docs/03-design-patterns.md))
- [ ] 릴리스 매니페스트(모델 리비전, 엔진, 프롬프트 해시, 도구 해시, 지식베이스, 가드레일, 평가셋)를 CI가 생성했다([13 13.9절](../docs/13-evaluation-guardrails.md))
- [ ] 출시 심사 패키지를 제출했고 모델 라이선스 심사를 통과했다([13 13.10절](../docs/13-evaluation-guardrails.md), [10 10.8절](../docs/10-models-serving.md))

**배포와 가용성**

- [ ] 모델 엔드포인트 복제본을 2 이상 배치했고, 네임스페이스당 복제본 상한을 설계에 반영했다([14 14.1절](../docs/14-operations.md), [14.4절](../docs/14-operations.md))
- [ ] 업그레이드 다운타임 창을 계획하고 사전 공지와 복구 검증 절차가 있다([14 14.3절](../docs/14-operations.md))

**관측과 대응**

- [ ] TTFT, 종단 지연, 오류율, GPU 사용률 기준선을 실측했고 알람 임계를 정했다([14 14.2절](../docs/14-operations.md), [14.8절](../docs/14-operations.md))
- [ ] OpenTelemetry 에이전트 추적이 실제로 표시되는지 확인했다([14 14.4절](../docs/14-operations.md))
- [ ] 온콜과 에스컬레이션 경로를 정했고, 플랫폼 SLA 항목을 온보딩 문서로 받았다([14 14.8절, 14.11절](../docs/14-operations.md))
- [ ] 배치 워크로드가 있으면 온라인 보호(전용 엔드포인트, 동시성 상한, 야간 윈도우)와 체크포인트를 정했다([14 14.9절](../docs/14-operations.md))
- [ ] 서비스 퇴역 절차와 기록 보존 범위를 정했다([14 14.12절](../docs/14-operations.md))

**백업과 복구**

- [ ] stateful 자산 5종(지식베이스, 모델, 에이전트 구성, MCP 등록, 세션)의 백업과 복구 방안을 정했다([14 14.7절](../docs/14-operations.md))
- [ ] 에이전트 구성 코드를 형상관리(Git)에 보관했다([08 8.8절](../docs/08-agent-builder.md))

**신원과 보안**

- [ ] 서비스 인증과 최종 사용자 신원을 분리했고, 사용자 인증과 권한은 앱이 강제한다([08 8.9절](../docs/08-agent-builder.md))
- [ ] 에이전트의 이그레스가 승인된 MCP 서버와 시스템으로 한정된다([09 9.9절](../docs/09-mcp-tools.md))

## A2.3 MCP 서버 등록 체크리스트

원격 MCP 서버 하나를 등록하고 승인하기 전 확인합니다([09](../docs/09-mcp-tools.md) 기반).

**연결 요건([09 9.5절](../docs/09-mcp-tools.md))**

- [ ] HTTP/HTTPS로 도달 가능하고, Streamable HTTP 또는 SSE를 지원한다(SSE는 `/sse` URL로 등록)
- [ ] 운영 환경은 HTTPS + 토큰 인증(`Authorization: Apikey <토큰>`)을 기본으로 한다
- [ ] HTTPS라면 발급자 인증서를 CA 신뢰 번들에 임포트했다

**도구 검토와 승인([09 9.4절](../docs/09-mcp-tools.md), [03 3.3절](../docs/03-design-patterns.md))**

- [ ] 각 도구의 능력과 입력 파라미터를 검토했고, 필요한 도구만 승인한다
- [ ] 도구 이름과 설명이 명확하고, 비슷한 도구가 중복 노출되지 않는다
- [ ] 읽기 전용 도구부터 노출하고, 쓰기 도구는 위험 등급과 승인 게이트를 먼저 정했다([07 7.2절, 7.3절](../docs/07-integration-write-design.md))
- [ ] 서버가 제공하는 도구 전부(숨긴 도구 없이)를 매니페스트로 받아 검토했다
- [ ] 승인 시점의 도구 이름, 설명, 입력 스키마의 해시를 기록했고, 바뀌면 승인을 무효화하는 감시가 있다([09 9.7절](../docs/09-mcp-tools.md))

**출처와 버전 — 외부에서 가져온 서버라면([⑤ 08 8.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md))**

- [ ] 공식 제공자 또는 검증된 저장소이고, 최근 갱신과 취약점 대응 이력이 있다
- [ ] 특정 릴리스 태그와 다이제스트로 고정했고 자동 갱신이 없으며, 내부 승인 레지스트리에서 설치한다
- [ ] 서버가 접속하는 외부 엔드포인트 목록이 이그레스 허용 목록과 일치한다([09 9.9절](../docs/09-mcp-tools.md))
- [ ] 설명 해시, 버전, 권한 범위 중 하나라도 바뀌면 재승인한다는 조건이 문서에 있다
- [ ] 신규 서버는 Streamable HTTP이고, SSE 서버라면 전환 계획이 있다([09 9.5절](../docs/09-mcp-tools.md))

**권한과 자격증명([09 9.7절](../docs/09-mcp-tools.md))**

- [ ] 도구가 사용하는 자격증명과 범위가 필요한 최소다(읽기로 충분하면 쓰기 권한 없음)
- [ ] 정적 토큰의 로테이션 주체와 주기를 정했고, 외부 시크릿 관리에 보관한다
- [ ] 서버가 에이전트 ID와 호출 사용자를 구분해 받는 전달 계약이 있어 공유 서비스 계정으로 사용되지 않는다([04 4.4절](../docs/04-identity-propagation.md))

**호스팅과 운영 — 사내에서 만든 서버라면([09 9.8절](../docs/09-mcp-tools.md))**

- [ ] 배치 위치(VKS 워크로드 또는 별도 VM, 컨테이너)를 정했다 — PAIS는 호스팅해 주지 않는다
- [ ] 가용성(복제본과 로드밸런서)과 동시 호출 부하를 가늠했다
- [ ] 서버 자체의 로그와 지표(호출 수, 오류, 지연)를 수집해 에이전트 추적과 상관 지을 수 있다
- [ ] 코드 실행 도구가 있으면 샌드박스(커널 수준 격리, 네트워크 기본 거부, 자원 한도)에서 실행한다([12 12.4절](../docs/12-service-security.md))
- [ ] 미사용 서버의 승인 해제와 자격증명 폐기 절차가 있다

## A2.4 위험 등급 판정 워크시트

유스케이스 하나당 한 장입니다. 네 질문의 답이 위험 등급을, 위험 등급과 첫 배치 규칙이 자율성 상한을 정합니다([02 2.9절, 2.10절](../docs/02-use-cases.md)). 이 두 값은 설계, 검증, 운영 문서가 모두 참조하는 입력이고, 서비스 레지스트리에 같은 값을 기록합니다.

| 유스케이스 | 판정자 | 날짜 | 재판정 예정 |
|------------|--------|------|-------------|
| | | | |

| 질문 | 답(예 / 아니오 / 확인 필요) | 근거와 검토자 |
|------|------------------------------|---------------|
| 법이 정한 고영향 영역에 해당하는가(에너지, 보건의료, 채용, 대출 심사 등) | | 법무 검토 결과: |
| 금융권이라면 감독 가이드라인의 위험 등급은 어디인가(상 / 중 / 하) | | 위험관리 조직 판정: |
| 개인정보나 기밀 등급 문서를 다루는가(지식베이스, 도구가 접근하는 데이터) | | 데이터 오너 확인: |
| 대외 노출인가 | | |
| 쓰기 권한이 있는가(A2.6의 작업 분류표 결과) | | |

**판정 결과**

- 위험 등급: ☐ 낮음 ☐ 중간 ☐ 높음 (낮음 = 내부 전용, 읽기 전용, 공개나 내부 등급 데이터, 고영향 비해당 / 높음 = 고영향 해당, 대외 노출, 비가역 쓰기, 금융 상 등급 중 하나라도)
- 자율성 상한: ☐ L0 ☐ L1 ☐ L2 ☐ L3 이상(예외 승인 필요) — 첫 배치는 L1 이하([02 2.10절](../docs/02-use-cases.md), [⑤ 08 8.3절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/08-agent-governance.md))
- 조회 전용 여부: ☐ 조회 전용 ☐ 학습 포함(별도 심의) ([02 2.11절](../docs/02-use-cases.md))
- 재판정 트리거: 대외 노출 전환, 쓰기 도구 추가, 데이터 소스에 개인정보나 기밀 추가, 고영향 영역 확장

## A2.5 신원 전파 계약

서비스 하나의 신원이 어느 경계에서 어떻게 전달되고 어디서 유실되는지를 표로 고정합니다([04](../docs/04-identity-propagation.md)). 패턴을 먼저 고르고 경계마다 채웁니다.

| 서비스 | 서비스 유형 | 전파 패턴(☐ A 관리형 + 서비스 범위 도구 ☐ B 자체 앱 + 사용자 범위 토큰 ☐ C 하이브리드) | 작성자 | 날짜 |
|--------|-------------|------|--------|------|
| | | | | |

| 경계 | 전달되는 신원 | 토큰 또는 수단 | 검증 주체 | 감사 필드 | 본문 |
|------|---------------|----------------|-----------|-----------|------|
| 사용자 → BFF | 사용자(IdP 클레임: 부서, 그룹, 등급) | OIDC Authorization Code + PKCE | BFF | 사용자 ID, 세션 ID, 요청 ID | [04 4.1절, 4.2절](../docs/04-identity-propagation.md) |
| BFF → PAIS 에이전트 또는 모델 엔드포인트 | 서비스 신원만(사용자 컨텍스트는 PAIS가 전파하지 않는다고 가정) | 서비스 토큰(Client Credentials) | PAIS 게이트웨이 | 서비스 ID, 요청 ID, 에이전트 ID | [04 4.2절](../docs/04-identity-propagation.md) |
| 앱 또는 에이전트 → MCP 도구 | ☐ 서비스 범위 ☐ 사용자 범위(토큰 교환, 위임 `act` 클레임) ☐ 서명된 컨텍스트 헤더 | | 도구 서버 | 원 사용자, 대리 주체, 도구, 스코프 | [04 4.3절, 4.4절](../docs/04-identity-propagation.md) |
| 앱 → 지식베이스 검색 | ☐ 지식베이스 단위 분리(관리형) ☐ 청크 ACL 필터(커스텀) | 사용자 권한 필드(부서, 그룹, 등급) | 검색 계층 | 필터 값, 반환 청크 ID | [04 4.5절](../docs/04-identity-propagation.md) |
| 장기 실행(토큰 수명보다 긴 다단계) | 재인증 또는 리프레시 정책 | | BFF | 재인증 시각 | [04 4.6절](../docs/04-identity-propagation.md) |

**확인 사항**([04 4.8절](../docs/04-identity-propagation.md))

- [ ] 인가 서버가 토큰 교환(RFC 8693)을 지원한다. 지원하지 않으면 서명된 컨텍스트 헤더로 대체하고 그 한계를 적었다
- [ ] PAIS가 사용자 컨텍스트를 도구와 검색까지 전파하는지 공식 문서로 확인했다. 확인 전에는 전파되지 않는다고 가정한다
- [ ] 사용자 집단이 여럿이면 에이전트와 지식베이스를 어떻게 나눴는지 적었다
- [ ] MCP 서버의 정적 토큰이 공유 서비스 계정으로 사용되지 않도록 전달 계약이 있다

## A2.6 쓰기 작업 분류표

서비스가 사내 시스템에 수행하는 모든 작업을 한 줄씩 적습니다([07 7.2절](../docs/07-integration-write-design.md)). 전송 이상이 하나라도 있으면 A2.4의 "쓰기 권한이 있는가"가 "예"입니다.

| 작업 | 유형(조회 / 생성 / 변경 / 전송 / 결제와 삭제) | 대상 시스템 | 되돌리기 | 영향 범위 | 승인 패턴(자동 / 제안 후 승인 / 대기 큐 / 드라이런) | 멱등 키(생성 주체, 저장 위치, TTL) | 보상 절차 | 다운스트림 한도(레이트, 동시성) |
|------|------|-------------|----------|-----------|------|------|-----------|------|
| | | | | | | | | |
| | | | | | | | | |

**승인 큐 설정**([07 7.3절](../docs/07-integration-write-design.md))

| 요소 | 값 |
|------|-----|
| 승인자(작업 유형별)와 요청자와의 직무 분리 | |
| 승인 대기 SLA와 만료 시 처리 | |
| 실행 조건(승인 뒤 대상이 바뀌면 재검토) | |
| 감사 필드(제안, 근거, 승인자, 시각, 결과, 변경 전 값) | |
| 킬스위치 위치와 작동 권한자 | |

- [ ] 첫 배치는 조회와 생성까지로 한정했다(전송 이상은 사람이 실행)
- [ ] 도구 입출력 스키마의 버전과 변경 시 회귀 절차가 있다([07 7.6절](../docs/07-integration-write-design.md))
- [ ] 도구 반환값을 비신뢰 입력으로 살균한다([07 7.7절](../docs/07-integration-write-design.md))

## A2.7 보호 문서 인입 승인

문서보안이 적용된 저장소를 검색 소스로 인입할 때 소스 하나당 한 장입니다([06 6.3절, 6.5절, 6.6절](../docs/06-data-onboarding.md), [⑤ 05 5.9절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/05-data-governance.md)). "전부 복호화"가 아니라 소스와 등급 단위로 결정합니다.

| 저장소 | 데이터 오너 | 등급 라벨의 출처(문서 관리 시스템, 보호 정책 ID) | 포함 등급(☐ 공개 ☐ 내부 ☐ 기밀 ☐ 제한 ☐ 국가핵심기술) | 인입 패턴(인제스트 시 복호화 / 쿼리 시 복호화 / 메타데이터만 / 미인입) | 지식베이스 분리(☐ 등급별 ☐ 부서별) | 조회 전용 | 승인자와 날짜 |
|--------|-------------|------|------|------|------|------|------|
| | | | | | | | |

**보안팀 정책 예외**([06 6.6절](../docs/06-data-onboarding.md))

- [ ] 복호화 서비스 계정과 허용 프로세스가 문서보안 정책에 등록됐다
- [ ] 대량 복호화 임계치와 알람이 정해졌다
- [ ] 정보보호위원회 심의 기록과 영향평가(개인정보 포함 시)가 있다
- [ ] 제한과 국가핵심기술 등급은 제외 목록에 있다

**운영 루프 값**([06 6.9절](../docs/06-data-onboarding.md))

| 항목 | 값 |
|------|-----|
| 재색인 주기 | |
| 권한 회수 반영 목표 시간(청크 비활성화까지) | |
| 재분류 절차와 정기 검토 주기 | |
| 복호화 로그의 보존과 대조 주기(C-16) | |

## A2.8 서비스 보안 체크리스트 서명표

[12 12.7절](../docs/12-service-security.md)의 게이트별 체크리스트를 통과했다는 증적과 서명을 남기는 표입니다. 항목 이름은 12.7절을 그대로 사용하고, 면제한 항목은 사유와 만료일을 반드시 적습니다([⑤ 07 7.5절](https://github.com/JaeHoYun/vcf-private-ai/blob/main/05-security/docs/07-audit-compliance.md)의 C-번호와 대응).

| 게이트(PoC / 파일럿 / 프로덕션) | 항목 | C-번호 | 상태(☐ 갖춤 ☐ 면제) | 증적 링크 | 면제 사유와 만료일 | 심사자 서명과 날짜 |
|------|------|--------|------|-----------|------|------|
| | | | | | | |
| | | | | | | |

- [ ] 면제 항목 중 만료일이 지난 것이 없다
- [ ] 12.4절 에이전트 위협 점검표의 해당 항목이 전부 "갖춤"이다
- [ ] 레드팀 임계값 통과 결과가 릴리스 매니페스트에 있다([12 12.6절](../docs/12-service-security.md), [13 13.9절](../docs/13-evaluation-guardrails.md))

## A2.10 온보딩 런북 기록

[05 5.1절](../docs/05-platform-consumption.md)의 일곱 단계를 거치며 실제로 받은 것과 걸린 시간을 적습니다. 이 기록을 서비스의 자산 목록으로 사용하고, 소요 시간은 플랫폼 팀에 공유합니다.

| 순서 | 단계 | 신청일 | 완료일 | 받은 것(식별자, 주소, 담당자) | 비고 |
|------|------|--------|--------|-------------------------------|------|
| 1 | 프로젝트와 네임스페이스, 쿼터 등급 | | | | |
| 2 | 모델 엔드포인트 접근(공유 또는 전용) | | | | |
| 3 | 서비스 신원과 토큰(OIDC 클라이언트) | | | | |
| 4 | 지식베이스 생성 권한과 데이터 소스 연결 | | | | |
| 5 | 도구 등록과 승인 | | | | |
| 6 | 관측 연결(수집기, 대시보드, 보존 정책) | | | | |
| 7 | 첫 호출(모델 목록, 챗 컴플리션, 검색) | | | | |

**플랫폼 SLA 항목 수령 확인**([14 14.11절](../docs/14-operations.md))

- [ ] 엔드포인트 가용성과 지연 목표
- [ ] 쿼터 증설과 지식베이스와 토큰 발급의 리드타임
- [ ] 업그레이드 사전 통지 기간, 모델 폐기 고지 기간과 병행 유지 기간([14 14.10절](../docs/14-operations.md))
- [ ] 장애 통지 채널과 시간, 지원 시간과 심각도별 응답 목표, 에스컬레이션 연락처
- [ ] 이너소스 저장소 위치와 기여 절차([05 5.6절](../docs/05-platform-consumption.md))
